## How it runs

`sh docker/asterisk/suite.sh` (after `sh docker/asterisk/lab.sh build` and `init`) builds the local `suite-runner` image from the main `Dockerfile` — the same pinned toolchain, whose `verify` stage runs fmt, clippy, all workspace tests and rustdoc for the commit — with the release app, `engine_lab` and `engine_network`, a private Xvfb and an AT-SPI stack from the pinned Ubuntu snapshot. Each scenario starts a fresh disposable PBX on the internal lab network (no published ports), runs as a non-root, read-only, capability-free container with the fictional `1001` account, and is torn down afterwards. GUI scenarios signal checkpoints; the host counts PBX contacts and channels at each one before the app continues. The image is a local test image and is never published.

Reports: `artifacts/suite/<UTC time>-<commit>/<scenario>/report.json` (result, observations, commit, uncommitted tracked changes, image ID, binary and log hashes) and `summary.json`.
