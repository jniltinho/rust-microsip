## How it runs

`sh docker/asterisk/suite.sh` (after `sh docker/asterisk/lab.sh build` and `init`) builds the local `suite-runner` image from the main `Dockerfile` (same pinned toolchain) with the release app, `engine_lab` and `engine_network`, a private Xvfb and an AT-SPI stack from the pinned Ubuntu snapshot. The `suite-build` stage is `FROM build`, which is `FROM verify`, so building the image runs fmt, clippy, all workspace tests and rustdoc for the same sources. The image is labelled with its commit; `SKIP_BUILD=1` refuses an image built from another commit. Each scenario starts a fresh disposable PBX on the internal lab network (no published ports), runs as a non-root, read-only, capability-free container with the fictional `1001` account, and is torn down afterwards. GUI scenarios signal checkpoints; the host counts PBX contacts and channels at each one before the app continues. The image is a local test image and is never published.

Reports: `artifacts/suite/<UTC time>-<commit>/<scenario>/report.json` (result, observations, commit, build-context changes now and at image build, image ID and reuse, phase timeouts, binary, script, log and capture hashes) and `summary.json`. The run fails when a requested scenario has no report, a report cannot be parsed, a phase times out, the container records a failure, or any lab container, network or volume is left. The fictional password file exists only during the run and is removed on every exit path.

Gates per scenario: engine-lab must exit 0 and report all five scenario rows (the example prints a row only after that scenario passed and exits non-zero on the first failure); engine-network checks the PBX contact and channels at each step; gui-link also checks that the call went to extension 602; exits after SIGTERM must print the app's "closed after signal" marker (a normal close, not death by the signal); the theme check requires a rendered dark window (between 5% and 40% brightness); every AT-SPI sweep must find its screen's marker control, at least five focusable nodes, no unnamed node and no read errors; a Tab cycle passes only when the first control to repeat is the first one focused, after at least 15 distinct controls including the tabs, Menu and the screen's key controls (End, XFER, HOLD and MUTE in a call); on the Phone screen Shift+Tab must step back. A run with changes in the build context or under `docker/asterisk` (PBX configuration and suite scripts) fails unless `ALLOW_DIRTY=1`.
