## Scope of this candidate

A native Linux (x86_64, glibc) SIP softphone written in Rust, with a compact
MicroSIP-inspired egui window. Verified so far only through synthetic PBX tests
against the disposable Asterisk lab (see `docs/receipts/`):

- UDP and TLS registration; outgoing and incoming G.711 PCMU/PCMA calls;
  answer, reject, BYE, CANCEL and CANCEL/200 OK races.
- Busy (486) on a second incoming call and do-not-disturb.
- RFC 4733 DTMF, hold/resume re-INVITE and blind transfer with NOTIFY.
- TLS + mandatory SRTP/SDES profile with certificate and downgrade negatives.
- SQLite contacts (multiple numbers, favorites), bounded CSV import, call
  history with filters, local search and 90-day retention.
- Single instance with a private local socket.

Artifacts: the ELF `rust-microsip` (primary) and a convenience AppImage that
wraps the byte-identical ELF and bundles no shared libraries. Both need glibc
2.39 or newer, `libasound.so.2` and, on X11, `libxkbcommon-x11` from the host.

## Known limitations

- **No human audio acceptance yet**: no clean-VM, headset or five-minute
  two-way human call on the exact artifacts (tasks 9.6, AUD-01).
- One account and one active call at a time; no conference, video, IM,
  presence, recording, call waiting UI or TURN.
- No acoustic echo cancellation: use a headset.
- No STUN/NAT traversal acceptance, network/suspend recovery or TLS custom-CA
  UX (tasks 4.6, 5.5); registration backoff consolidation pending (4.1).
- Device selection/hotplug, mute/local test, resampling and jitter buffer are
  not accepted (5.1–5.3).
- Configuration precedence, Secret Service, migrations/backups, TOML
  import/export and `--doctor` are pending (3.1–3.6).
- Tray, URI handler integration and bounded shutdown are pending (8.1, 8.2, 8.4).
- Not full MicroSIP parity; the CLI/MCP agent extension is not included.
- No independent attestation: checksums give integrity, not authorship.
  Rust toolchain archives are pinned by SHA-256 over HTTPS, not PGP-verified.
- The SBOM (`scaffold-sbom.cdx.json`) is a preliminary build inventory, not a
  reviewed release SBOM or an ELF link map; no `cargo deny`/`cargo audit` run.

## Verify a download

```sh
sha256sum --check --strict SHA256SUMS          # all exported files
grep -E 'rust-microsip(-.*AppImage)?$' SHA256SUMS | sha256sum --check --strict -
./rust-microsip --version
# AppImage without FUSE:
./rust-microsip-<version>-x86_64.AppImage --appimage-extract-and-run --version
# Confirm the AppImage wraps the same ELF (from a source checkout):
sh packaging/appimage/verify.sh rust-microsip-<version>-x86_64.AppImage rust-microsip
```

`build-manifest.json` lists the SHA-256 of every source file that entered the
build; compare it with the tagged commit to identify the artifact's origin.

## Build it yourself (Docker only, no host Rust)

```sh
sh packaging/release/clean-clone-build.sh <commit-or-tag> <empty-dir> [reference-SHA256SUMS]
```

It clones the committed revision (no `base/`, `artifacts/` or uncommitted
files), builds the `artifacts` target with the pinned builder, checks
`SHA256SUMS`, and requires every exported file to be listed. `NO_CACHE=1`
forces a full rebuild. Bit-for-bit identity across machines is not yet claimed.

## Rollback

- The application uses its own XDG identifier (`rust-microsip`) and never reads
  or changes legacy MicroSIP/GOnnect data; the previous softphone stays usable.
- Keep the previous ELF/AppImage file; rolling back is replacing the file.
- With the application closed, back up `$XDG_DATA_HOME/rust-microsip/`
  (default `~/.local/share/rust-microsip/`, SQLite plus WAL files) and
  `$XDG_CONFIG_HOME/rust-microsip/config.toml` before upgrading. An older
  build rejects a database with a newer schema instead of downgrading it, so
  restore the backup taken with the older version; do not edit the database.
- Remove any desktop entry/URI handler you registered manually if you drop
  the application entirely.
