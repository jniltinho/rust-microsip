# ADR 0007 — synthetic hold/resume and rejected re-INVITE

Date: 2026-10-12. Status: accepted for isolated evaluation only. Baseline: `ac9248d`. Not production, full SIP-06, task 1.7, G0 or release approval.

## Decision

Add an opt-in project-owned hold probe using the existing experimental `rsipstack` adapter and G.711/RTP primitives. No dependency, native backend, copied upstream implementation/table or asset is adopted. The selected Cargo/license inventory remains unchanged; `rustrtc` is not adopted. The shipping CLI remains a static scaffold.

A changed SDP offer retains its origin session identity and increments the version. Hold uses `sendonly`, requires a `recvonly` answer and locally pauses the synthetic sender; resume uses `sendrecv`. These choices follow [RFC 3264](https://www.rfc-editor.org/rfc/rfc3264.html). An incompatible codec re-INVITE must receive 488 without losing the established dialog or media, with ACK for the final response, following [RFC 3261](https://www.rfc-editor.org/rfc/rfc3261.html). No standard text or reference code is embedded.

## Experiment

`g0_calls::hold::probe_hold_pair` admits only matched fictional 1001/1002 UDP, 1101/1102 TCP or 1301/1302 TLS pairs at one explicit IPv4 registrar. The public API accepts the caller's registrar address; it is not a network sandbox. The example fixes DNS to the disposable PBX. TLS validates SIP CA/SNI but **all RTP is plaintext UDP**. Mandatory-SRTP 1201/1202 are refused before networking, never silently downgraded.

Twelve cases cover three signaling transports, PCMA/PCMU and both origination/holding directions. Two endpoints in one process have separate signaling/media sockets, with distinguishable 440/880 Hz sources. Each call measures two seconds before hold, one second held (250 ms receive settling), two seconds resumed and two seconds after a rejected incompatible-codec offer. Arrays are ordered **originating/holding endpoint, receiving endpoint**, including reverse cases.

Each voice window requires ≥80 emitted and accepted frames per endpoint, RMS 1000–10000 and expected-remote/own-tone power ratio ≥20. During hold the originating endpoint must emit zero frames and accept zero PBX audio frames after settling, while the peer must still emit at least 40 frames over the entire one-second held window (including settling); its estimated remote-tone amplitude must remain <100. Absence of frames yields zero amplitude. This proves local suppression and restored synthetic two-way audio in this fixture, not that the far endpoint received a forwarded hold re-INVITE: anchored Asterisk can keep its opposite leg sendrecv. It does not establish a human mute/hold UX, music-on-hold or remote-originated hold interoperability.

The adapter checks 200/direction for hold/resume, stable anchored hold/resume destinations, three strictly increasing re-INVITE CSeqs, final 488, unchanged exact dialog identities/confirmed state, and both dialogs terminated after BYE/200, followed by authenticated unregistration. The SDK auto-ACKs final INVITE responses. A bounded inspector correlates emitted ACKs to the bound Call-ID and CSeq/method, with at most sixteen new INVITEs; invalid method evidence fails and notifies the waiter. This observes the pre-send SDK boundary, **not independent packet capture or remote ACK reception**. Initial ACK reception and BYE/200 observations use the existing adapter inspectors.

## Bounds and remaining gates

SDP is restricted to one anchored G.711 stream (8 KiB, 128 lines, 512 bytes/line). A single explicit direction or implicit sendrecv is accepted; this fixture requires recvonly rather than also accepting an inactive hold answer. Duplicate session/media direction overrides and zero-address legacy hold are rejected. This is not a general SDP implementation. Incoming update handling is opt-in; ordinary pair-call/IVR probes retain their prior mode. Its pure answer helper is unit-tested, but the final anchored-PBX hold run does not prove that the receiving Rust endpoint handled a forwarded re-INVITE or generated the 488 (the PBX generated that rejection). The helper discards a changed remote media target; dynamic retargeting remains a production-actor gate. Endpoint state watchers still are not a general per-dialog production actor.

Media uses fixed synthetic initial SSRC/sequence/clock values, one 20 ms pacing interval, constant frame buffers and a bounded 128-datagram phase drain. Send sequence/clock persist across phases, but the clock advances only in measured windows, not across re-INVITE signaling gaps, and receive continuity tracking restarts each window: this does not prove cross-hold receive continuity, RTCP, jitter/loss recovery, randomness, resampling or devices. The source tone's phase does not advance while locally muted. Each operation has a 30-second total timeout/cancellation; the Compose wrapper has a 360-second outer deadline and teardown trap. Failure/cancellation drops local tasks/sockets without guaranteed remote BYE/unregister, so disposable PBX teardown remains mandatory.

[ADR 0004](0004-experimental-sip-adapter.md) and [ADR 0005](0005-own-g711-and-synthetic-rtp.md) parser/channel bounds, credential copies/zeroization, unsolicited-call and authenticated failure-path cleanup gates remain. Raw fixture reads are bounded/preallocated, but serde and dialog credential copies are not comprehensively zeroized. A separate-process Docker/PBX observer, written by the implementing agent, corroborates lifecycle, hardening and actual running image/ELF identities, not SDP/RTP content or an independent third-party execution. Its source/hash is retained only in ignored local evidence; the public lab command does not invoke that observer. The pre-run identity snapshot binds running artifacts, not an embedded source-manifest attestation. The [receipt](../receipts/g0-rust-hold-2026-10-12.md) records executed checks and regressions.

DTMF/IVR and hold are separate experiments, not a combined production SIP-06 workflow. REFER/NOTIFY, mandatory SRTP/SDES and downgrade negatives, production media/call actors, human five-minute exact-artifact voice/history, host/VM/NAT/IPv6, desktop/IPC ELF and CLI/MCP acceptance remain required. No task is checked off or narrowed, and no release is authorized.
