# ADR 0006 — negotiated RTP DTMF and isolated IVR proof

Date: 2026-10-12. Status: accepted for isolated G0 evaluation only. Baseline: `ca43366`. This does not approve production use, full SIP-06, task 1.7 or G0.

## Decision and provenance

Extend the project-owned media primitives with allocation-free DTMF payloads and a finite transmission iterator. No new Cargo dependency, native backend, copied source/table or asset is adopted. The selected registry inventory and license boundary from [ADR 0005](0005-own-g711-and-synthetic-rtp.md) remain unchanged. `rustrtc` is not adopted.

The protocol reference is [RFC 4733](https://www.rfc-editor.org/rfc/rfc4733.html). Negotiate a dynamic `telephone-event/8000` payload and permitted events; without an event list, assume DTMF 0–15. Audio and events share SSRC, sequence space and clock base. Each digit retains its onset timestamp, marks its first packet, increases duration and sends three identical final reports. Serialization clears the reserved bit; parsing ignores that received bit. This is a short single-event DTMF primitive, not segmented long holds, multiple events in one payload, receive-side playout or SIP INFO fallback. No standard text or reference implementation is embedded.

## Experiment boundary

The opt-in `g0_controls` example calls only fictional IVR 601 through the existing experimental SIP adapter. Each UDP/TCP/TLS × PCMA/PCMU combination sends `123` and `124`. The PBX reads three digits and selects different 1 kHz/400 Hz branches. The receiver must measure the expected, not the opposite, tone. The six positive `123` outcomes prove recognized RFC 4733 digits because no in-band digit audio is sent. The six `124` outcomes demonstrate non-acceptance; 400 Hz also follows absent input/timeouts, so they do not independently prove recognition of the final `4`. This tests an actual PBX outcome rather than merely counting locally emitted packets.

Only IPv4 1001/UDP, 1101/TCP and 1301/TLS **plaintext RTP** are admitted. Mandatory-SRTP 1201/1202 are refused, not downgraded. Validated SIP TLS does not encrypt RTP. The dialed URI is fixed to 601, with no arbitrary CLI digit input, microphone, personal profile or shipping control command. The public probe still accepts a caller-supplied validated IPv4 registrar address; only the opt-in example fixes DNS to the disposable PBX. This is not a sandbox for untrusted library callers. Each operation has a 30-second total deadline; owned background tasks cancel on drop. The wrapper has a 200-second deadline and teardown trap. Exactly one Rust overlay must be selected; the normalized checker rejects a runner/image/target from another profile.

SDP is restricted to the existing anchored single G.711 stream plus the offered dynamic event payload, 8 KiB, 128 lines and 512 bytes/line. The fixed sequence is checked against the entire negotiated event mask before transmission. The sender uses constant storage, one 20 ms pacing interval, fixed synthetic rollover values, three 120 ms digits, repeated end reports and inter-digit silence. A loopback UDP test independently checks the actual sender's shared sequence/clock/SSRC, rollover, marker and end reports with dynamic payload 111; actual PBX negotiation uses 101.

After priming/digits, at most 128 queued pre-branch datagrams are discarded. Two seconds of incoming negotiated audio must produce at least 80 accepted frames, RMS 1000–10000 and expected-to-opposite tone power ratio ≥20. Source, payload, frame size, stable SSRC and sequence/timestamp continuity are checked. This is not a hostile-network/jitter-buffer guarantee. Success requires ACK emission, BYE/200, exact dialog confirmed/terminated state, endpoint phase observations and authenticated unregistration. These are in-process checks, not independent wire capture. External PBX counts/contact queries corroborate successful cleanup, not RTP tone content.

## Remaining gates

[ADR 0004](0004-experimental-sip-adapter.md) and ADR 0005's upstream parser/channel bounds, secret-copy and failure-path teardown gates remain. The new example preallocates its bounded read buffer but does not prove zeroization of every error-path/serde allocation or dialog-lived `InviteOption` credential clone. Endpoint-wide callbacks are not a general per-dialog event contract. The lab sender offers only event payload 101 and fails closed on a different answer; its parser relies on prior single-stream validation. Reused LabEndpoint can auto-answer one unsolicited INVITE; production caller-only mode needs rejection. Synthetic initial RTP values are not randomized, and the loopback wrap is after, not inside, the digit. There is no RTP sending during the two-second branch measurement and no RTCP. Failure/cancellation drops local tasks/sockets without guaranteed remote BYE/unregistration; disposable PBX teardown is still required.

The [executed IVR receipt](../receipts/g0-rust-dtmf-2026-10-12.md) is partial task 1.7 evidence only. Hold/resume, REFER/NOTIFY, mandatory SRTP/SDES and downgrade rejection remain unimplemented; full SIP-06 includes restored audio after hold. Human headset/exact-artifact acceptance, RTCP/jitter/resampling/devices, host/VM/NAT/IPv6, complete-stack ELF and CLI/MCP remain required. No task criterion is reduced and no release is authorized.
