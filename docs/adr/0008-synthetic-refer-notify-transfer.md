# ADR 0008 — Synthetic REFER/NOTIFY transfer evaluation

Date: 2026-10-12. Status: accepted experimental boundary, not a production transfer actor, complete SIP-08, G0 or release approval. Baseline: `327326b`. See the [executed receipt](../receipts/g0-rust-transfer-2026-10-12.md).

## Decision

Add an opt-in `g0_calls::transfer` probe behind the existing experimental rsipstack 0.7.3 adapter. Two synthetic Rust endpoints use distinct signaling/RTP sockets in one runner process; pinned andrius/asterisk remains the separate, media-anchoring PBX. The shipping CLI still does not register or dial. No new dependency, crypto provider, upstream implementation or asset is adopted; [ADR 0003](0003-g0-license-and-native-boundaries.md) and [ADR 0004](0004-experimental-sip-adapter.md) remain controlling adoption boundaries. The newly documented Rust reference projects are not replacement dependencies.

## Result correlation

[RFC 3515](https://www.rfc-editor.org/rfc/rfc3515.html) separates REFER acceptance from the referred action's status, conveyed by a dialog-matching `refer` NOTIFY with a `message/sipfrag` body. NOTIFY can arrive before the REFER transaction completes. The Event id, when present, identifies the REFER CSeq, not the NOTIFY CSeq; it is optional for the first REFER in a dialog. These points inform this narrow first-transfer fixture, not a claim of general event-package compliance.

The private subscription is armed with the established Call-ID/local-tag/remote-tag before sending REFER. It records the outgoing REFER CSeq at the SDK pre-send inspector. A NOTIFY must match both the SDK dialog identity and parsed request tags/Call-ID, have unique required headers, a `refer` Event with a matching optional id, typed NOTIFY CSeq, the permitted content type/subscription state and a bounded status-line body. Older CSeqs, conflicting same-CSeq status/state, provisional terminal status and new progress after termination are rejected. Same-CSeq parsed status/state duplicates are idempotent; this is not byte-identical replay validation.

An accepted REFER alone never publishes an outcome. Neither does an active subscription containing a 200 sipfrag. Completion requires accepted REFER, terminal NOTIFY with final sipfrag status and observation of its matching 200 reply at the SDK pre-send boundary. A watch channel retains the result, including when NOTIFY precedes the REFER response. No lock spans an await. The reply observation is **not** proof that Asterisk received the response; runtime tone and lifecycle checks provide separate corroboration.

Bounds are deliberately narrow: sipfrag ≤1024 bytes, ≤16 lines, ≤256 bytes/line and ASCII/control checks; Event/subscription fields ≤256 bytes and content type ≤128. Only the fixture's `message/sipfrag[;version=2.0]`, active/pending with optional numeric expires and terminated with optional `reason=noresource` forms are accepted. Unknown parameters fail closed. One subscription permits ≤16 distinct NOTIFYs and ≤4 increasing outgoing REFER attempts; a new REFER after notifications fails the operation. Endpoint event observation is capped at 64. Each entire pair operation has a 30-second deadline and owned cancellation; the public lab wrapper has a 720-second deadline and teardown trap. These limits do not bound the upstream parser/transport/transaction queues.

## Actual transfer and preserved-call checks

The public probe permits only fixed matched IPv4 fictional account pairs: UDP 1001/1002, TCP 1101/1102 and validated-TLS 1301/1302. Destination is an enum, never an arbitrary Refer-To URI: route 602 emits a mathematical 1 kHz tone; route 699 is deliberately absent. Mandatory-SRTP 1201/1202 are refused, not downgraded. Incoming REFER is not an automatically authorized calling interface.

Each of 24 cases establishes the original two-endpoint call and measures two seconds of independent 440/880 Hz two-way media. For successful transfer, terminal 2xx NOTIFY must be followed by measured 1 kHz media at the transferee, then clean termination. The transferor handles either PBX termination or its own BYE without assuming both happen in a fixed order. For failed transfer, terminal failure must leave the exact original dialog identities confirmed, followed by two more seconds of measured two-way 440/880 Hz media before BYE. Both original dialogs must terminate and both authenticated unregisters must succeed. The actual fixture returned REFER 202 and final NOTIFY 200 or 404; 202 alone is never enough.

Every voice/tone window requires ≥80 transmitted and accepted frames, RMS 1000–10000 and remote/own-frequency power ratio ≥20. The post-transfer 1 kHz peak amplitude must additionally be finite and ≥4000: a ratio against the transferee's own frequency alone can mistake leakage from the former partner's 880 Hz tone for the new destination. A real red test reproduced that weakness; corrected tests reject 880 Hz and accept 1 kHz through both G.711 codecs, and reject weak/non-finite measurements. Arrays are originating/transferring endpoint first, even in reverse cases. Asterisk anchors media; reused incoming-offer handling does not establish general retargeting or forwarded-update coverage. RTP clocks advance only inside windows, and receive tracking resets per window. TLS protects SIP signaling here; media is explicitly plaintext UDP RTP, **not SRTP**.

## Evidence and remaining gates

Tests cover bounded parsing, REFER/Event correlation, 202/provisional/active-final non-completion, early final NOTIFY, duplicate handling, malformed/foreign dialogs, finite notification failure, pre-cancellation and mandatory-SRTP refusal. They do not exhaust asynchronous interleavings or hostile-network behavior. The separate-process observer written by the implementing agent validates complete matrix coverage and adversarial matrix controls, matches actual running images/ELFs to pre-run snapshots, observes PBX lifecycle counts, checks container hardening and verifies clean teardown. It remains ignored locally; ordinary public lab commands do not run its additional checks. It does not independently decode SIP/SDP/RTP or attest source-to-image provenance.

Shared endpoint changes require rebuilt pair-call, RFC 4733 IVR and hold/resume/rejected-offer regressions, recorded in the receipt without rewriting historical evidence. Source hashes identify 34 application build inputs, not a production desktop/IPC/audio stack. The selected inventory remains 73 packages/143 preserved notice files.

Production remains gated on dialog-scoped actors and state transitions, upstream/parser/channel bounds, credential-copy lifetimes, complete error/cancellation remote cleanup, multiple-operation/refresh semantics, media continuity/retargeting, jitter/RTCP/devices, mandatory SRTP/SDES and downgrade negatives. The example's final raw read buffer is Zeroizing, but serde scratch/reallocated buffers and SDK/InviteOption credential Strings are not fully erased. No raw SIP/SDP/auth/audio or call identifiers are emitted; aggregate metrics are not a general no-leak certification. Human exact-artifact audio, desktop/IPC ELF, persistence, CLI/MCP and clean-VM/release gates remain mandatory. Task 1.7 and production task 4.5 stay open with their original criteria.
