# Disposable Asterisk lab

**Disposable signaling/synthetic-media infrastructure, not a working softphone or completed G0.** Based on the user's requested [andrius/asterisk](https://github.com/andrius/asterisk) project, pinned to Asterisk 22.11.0 and an exact linux/amd64 image manifest. See [provenance and license boundaries](../../docs/adr/0002-disposable-asterisk-lab.md) and the [executed receipt](../../docs/receipts/asterisk-lab-2026-10-12.md).

## Prerequisites

- Linux, Docker Engine **28.0.0 or newer**, BuildKit/buildx and Compose with `!override` support. Tested with Engine 29.1.3 and Compose 5.6.0. Older engines have a [localhost port-publishing exposure caveat](https://docs.docker.com/engine/network/port-publishing/).
- Run as your ordinary non-root user with Docker access. Scripts propagate that numeric UID/GID; they do not change host permissions or install host packages.
- POSIX shell and GNU `timeout`; `config-check` additionally uses host Python 3 (standard library only). Runtime Python/OpenSSL/Asterisk come from the pinned container.
- Run commands below from the repository root. Only the image build needs registry access. Default runtime networking is internal; no host ports are published.

## Build and test

```sh
sh docker/asterisk/lab.sh build
sh docker/asterisk/lab.sh init
sh docker/asterisk/lab.sh unit-test
sh docker/asterisk/lab.sh config-check
sh docker/asterisk/lab.sh test
```

`init` creates new random fictional passwords and a three-day private CA/server certificate under ignored `artifacts/asterisk-lab/`, requiring an empty, real, owned 0700 directory. It never overwrites an existing lab. Do not print, commit, upload, or reuse these credentials. CA private keys are kept only in `issuer/`, never mounted; the PBX and clients get separate read-only directories. Clients never receive the server key. Passwords have **no intrinsic expiry**: teardown stops their use but leaves their files on disk.

`test` runs the PBX, a registration peer and a registration-only probe with a 120-second outer deadline (20-second kill grace). It checks UDP/TCP/TLS digest challenges and authenticated registration, rejects a wrong password on all three transports and an unknown TLS CA, then unregisters and removes containers/networks/volumes. Sanitized-by-design operational logs stay ignored in `artifacts/asterisk-smoke.log`; do not publish raw logs. Exit 0 is required, not merely an “Asterisk Ready” line.

The peer registers 1002/1102/1202 and renews every 60 seconds; **it does not answer calls**. The probe registers 1001/1101/1201. It is a small infrastructure fixture, not the candidate Rust SIP stack. Its receipt explicitly says `calls_tested=false` and `g0_passed=false`.

## Opt-in Rust registration proof

With fresh lab fixtures generated by the current image (including the valid unrelated CA):

```sh
docker buildx build --platform linux/amd64 --target g0-registration-runner --load \
  -t rust-microsip-g0-registration:0.1.0-lab.1 .
sh docker/asterisk/lab.sh rust-test
```

The default-off `compose.rust-g0.yaml` replaces the test runner and disables PBX Contact rewriting for the internal-only proof, retaining the internal network, non-root identity, read-only filesystem/mount and zero ports. Its Rust example uses the actual experimental adapter with a ten-second deadline per cycle, register/explicit refresh/unregister, three wrong-password cases, valid unrelated CA and wrong-hostname rejection. Outgoing Contact correctness, stable Call-ID and increasing phase CSeq are checked and reported as booleans only. It accepts no arguments or personal account settings. The wrapper has a 120-second outer deadline and cleanup trap; ignored logs are `artifacts/rust-registration-smoke.log`. Original Python fixture tests remain available through `test`. The runner is a local lab artifact, not an attested release image.

The [Rust receipt](../../docs/receipts/g0-rust-registration-2026-10-12.md) and [ADR 0004](../../docs/adr/0004-experimental-sip-adapter.md) describe the narrow approval and upstream channel/secret-lifetime risks. Notice/source inventory is preserved in the runner image. **Neither probe answers calls or proves PCMA/PCMU, SRTP, media, renewal scheduling, hostile-network resilience or a usable release.** Task 1.6 remains open.

## Opt-in Rust synthetic calls

```sh
sh docker/asterisk/lab.sh calls-build
sh docker/asterisk/lab.sh calls-test
```

`compose.calls-g0.yaml` is default-off. It disables the Python peer and runs two independently bound Rust endpoints in one runner process. The normalized configuration must contain only the PBX and exact Rust runner, on the internal network without ports, with non-root/read-only/capability-drop restrictions and separate private read-only mounts. PBX Contact rewriting is disabled for incoming reachability proof. Select exactly one Rust overlay; do not combine registration, calls and controls overlays.

The runner executes UDP/TCP/TLS × PCMA/PCMU × both origination directions: 12 calls, five seconds each. It verifies INVITE/200/ACK, distinct 440/880 Hz sources received at the other endpoint, negotiated RTP source/codec/SSRC/sequence/timestamp checks, BYE/200, termination and unregistration. It emits only aggregate measurements. TLS uses **1301/1302 plaintext RTP**, never mandatory-SRTP 1201/1202; no downgrade or SRTP success is claimed. A normalized-Compose identity test rejects a wrong image, command, proof mode or port publication.

`calls-test` has a 200-second outer deadline and cleanup trap; raw operational logs stay ignored in `artifacts/rust-calls-smoke.log`. Rebuild after source changes. Reuse only still-valid fictional fixtures, or stop the lab and remove its explicitly named ignored directory before `init`; do not overwrite personal settings. See [ADR 0005](../../docs/adr/0005-own-g711-and-synthetic-rtp.md) and the [executed media receipt](../../docs/receipts/g0-rust-media-2026-10-12.md). No microphone/headset, recording, SRTP, DTMF, hold, transfer, loss/jitter, host/VM media or release artifact is tested by this command. G0 remains open.

## Opt-in negotiated DTMF IVR proof

With still-valid fictional fixtures:

```sh
sh docker/asterisk/lab.sh controls-build
sh docker/asterisk/lab.sh controls-test
```

`compose.controls-g0.yaml` selects one Rust caller and the PBX only, preserving the internal port-free network, private mounts and runtime hardening. It runs UDP/TCP/TLS × PCMA/PCMU × two IVR inputs: 12 calls to fictional 601. Correct `123` must yield 1 kHz; incorrect `124` must yield 400 Hz. The sender uses negotiated RFC 4733, not SIP INFO or in-band tones. The runner checks two seconds of decoded PBX branch audio, ACK emission, BYE/200, exact dialog termination and unregistration. Only aggregate metrics are emitted.

TLS uses explicit plaintext-RTP 1301; mandatory-SRTP accounts are rejected. No hold, REFER, SRTP, human/audio-device or release acceptance is claimed. `controls-test` has a 200-second outer deadline and cleanup trap; ignored logs are `artifacts/rust-controls-smoke.log`. The checker validates this overlay's exact image/build target. Rebuild after source changes and do not combine overlays. See [ADR 0006](../../docs/adr/0006-negotiated-rtp-dtmf.md) and the [executed receipt](../../docs/receipts/g0-rust-dtmf-2026-10-12.md). Task 1.7/G0 stay open.

To leave the isolated PBX/peer up temporarily:

```sh
sh docker/asterisk/lab.sh up
sh docker/asterisk/lab.sh down
```

Do not run the default and host profiles concurrently: they share one Compose project. The default has no host networking, published ports, privileges, devices, Docker socket, desktop session, HOME, or production configuration mounts. Filesystem is read-only except private tmpfs. Resource limits and explicit module loading bound the fixture; they are not a defense against every vulnerability in an upstream image.

## Opt-in synthetic hold/resume proof

With current still-valid fictional fixtures and the PBX wrapper built:

```sh
sh docker/asterisk/lab.sh hold-build
sh docker/asterisk/lab.sh hold-test
```

`compose.hold-g0.yaml` selects only two Rust endpoints in one runner process and the PBX, with separate sockets, private read-only mounts, no published ports and the existing hardening. Do not combine overlays. Twelve UDP/TCP/TLS × PCMA/PCMU × both-direction calls check sendonly/recvonly hold, local zero-transmit suppression, resumed synthetic two-way audio and preserved media after a 488 incompatible-codec re-INVITE. ACK evidence is correlated emitted SDK messages, not independent packet capture. Asterisk's anchored opposite leg can remain sendrecv; this is not a remote-hold or music-on-hold acceptance test.

Each call has a 30-second deadline; `hold-test` has a 360-second outer deadline and cleanup trap. Ignored logs are `artifacts/rust-hold-smoke.log`. Rebuild after source changes. TLS uses explicit plaintext-RTP 1301/1302; mandatory-SRTP fixtures are refused. Only aggregate metrics are emitted. No devices, human audio, REFER/SRTP or release acceptance is claimed. See [ADR 0007](../../docs/adr/0007-synthetic-hold-and-resume.md) and the [executed hold receipt](../../docs/receipts/g0-rust-hold-2026-10-12.md). Task 1.7, full SIP-06 and G0 stay open.

## Fictional dialplan and security fixtures

| Extensions | Signaling | Media policy |
| --- | --- | --- |
| 1001 / 1002 | UDP | Explicit insecure lab RTP |
| 1101 / 1102 | TCP | Explicit insecure lab RTP |
| 1201 / 1202 | Validated TLS | Mandatory SDES SRTP, no optimistic downgrade |
| 1301 / 1302 | TLS | Explicit RTP-only fixture (positive plain-RTP calls; negative secure-media policy), not a secure production default |

All use G.711 PCMA/PCMU and RFC 4733 DTMF, with PBX-anchored media (`direct_media=no`). Exact local destinations only: no wildcard/PSTN routes, outbound trunks, anonymous endpoint, remote administration or recording.

- `600`: echo.
- `601`: read exactly three DTMF digits; `123` produces 1 kHz, other input 400 Hz.
- `602`: generate a 1 kHz tone for 20 seconds.

These routes and the SRTP module pass PBX readiness checks. **Route 601 now has positive/negative Rust RFC 4733 call evidence. Routes 600/602 and mandatory SRTP remain untested by Rust.** TLS 1.2 is the explicit current lab server method; this is not a claim of TLS 1.3 coverage.

## Opt-in host loopback profile

```sh
sh docker/asterisk/lab.sh config-check
sh docker/asterisk/lab.sh host-up
# Use only a fictional lab client, never the installed personal profile.
sh docker/asterisk/lab.sh host-down
```

The host profile publishes **only** 127.0.0.1:15060 UDP/TCP (SIP), 127.0.0.1:15061 TCP (TLS), and 127.0.0.1:10000–10019 UDP (RTP). Its non-internal Docker bridge allows container egress; there are still no trunks. The peer and probe are profiled out. The CA includes `pbx`, `localhost` and 127.0.0.1; never disable CA/hostname verification. The selected configuration advertises loopback signaling/media and forces anchoring.

`config-check` validates actual normalized Compose output, not just YAML text. **Host registration, SDP rewriting, actual host media, and ACL behavior are not yet acceptance-tested.** No VM acceptance profile exists yet. Do not expose this host profile to VMs, a LAN, wildcard interfaces or production networks. Task 1.5 remains open.

## Teardown and secret deletion

Always stop the active profile first. `down`/`host-down` remove disposable runtime resources, but intentionally leave ignored credentials and logs for local diagnosis. After teardown, remove **only** `artifacts/asterisk-lab/` using your file manager or an explicitly checked repository-relative path; then `init` can create a fresh lab. Do not delete or alter personal SIP settings, the installed AppImage, or `base/`.

Generated certificates become unusable after three days. Tests fail closed on stale credentials/certificates, unsafe permissions, nonempty generation paths, missing mount directories, or mismatched Compose contracts. Regenerate only after stopping the lab and removing its old disposable directory.

## Remaining gates

Registration and Claude review do not establish any of these results. Do not publish the inherited image without a separate complete license/source/asset audit.
